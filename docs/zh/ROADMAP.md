# Fyrlet 路线图

[English](../ROADMAP.md) | 简体中文

更新：2026-11-08。本文说明工作的优先级、依赖和完成条件，不作为版本发布日期承诺。项目尚未上线，接口调整可直接替换，同步更新服务端、SDK、示例与文档。阶段 1–5 已完成本地交付，包含 React 适配、契约类型、有限重试与 OIDC 登录示例；真实外部 IdP、生产部署及正式发布仍按各自边界验收。能力与验证记录见 [STATUS.md](STATUS.md) 和 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 发展方向

围绕真实应用，完善从业务调用、实时订阅到界面状态的完整开发流程。重点是让开发者能够判断写入是否完成、减少组件之间的重复状态管理，并顺利接入登录体系。

继续采用 Phoenix、PostgreSQL、命名 Operation 和有界 Subscription。协议与一致性规则由核心维护；客户端状态管理、UI 适配与登录示例按独立模块交付。产品范围与架构约束见 [PRODUCT.md](PRODUCT.md) 和 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 阶段安排

P0 优先处理结果与一致性语义，P1 完善应用开发流程，P2 按实际需求评估。阶段编号用于组织交付，能够独立验证的工作可以并行开展。

| 阶段 | 优先级 | 交付目标 | 依赖 |
| --- | --- | --- | --- |
| 1. 写入结果与视图确认 | P0 | 1A 明确操作与未知结果，1B 确认订阅已更新 | 先明确结果语义；视图确认单独设计与验证 |
| 2. 共享客户端查询与 React 接入 | P1 | 订阅复用、selector、独立 React 适配包及真实页面 | 可与阶段 1 独立推进 |
| 3. 契约类型补全 | P1 | Presence 类型、操作类别与显式运行时元数据 | 可与阶段 1、2 独立推进 |
| 4. 短暂失败的有限重试 | P1 | 显式启用、使用固定幂等键的有界重试 | 依赖 1A 的结果语义与服务端幂等保证；阶段 3 可提供调用元数据 |
| 5. 登录桥接与完整应用验收 | P1 | 登录、续期、退出、身份切换及客户端状态清理 | 登录示例可先做；最终结合前面各阶段验收 |

## 执行顺序与决策点

- 保持已交付的 1A 结果分类、幂等键与回执恢复规则，以及 1B 的关联式权威刷新；操作提交与视图确认分别可观察。
- 已在查询复用基础上交付 React 适配与 Inbox 页面，并串联类型化调用和 OIDC 登录桥接。后续根据实际应用反馈决定是否增加 API。
- 有限重试依赖 1A 和调用入口的幂等保证，不要求等待 1B 完成。是否等待视图更新由应用单独选择，不能把服务端写入成功与界面追平合成同一个结果。
- 每项交付都先定义可观察行为、资源上限和失败处理；方案未明确的条目保持计划状态。当前实现进度统一记录在 [STATUS.md](STATUS.md)。

## 阶段 1：写入结果与视图确认

进度：**1A、1B 已交付。** `mutate` 提供结果生命周期与独立的 `views` 结果，`call` 保留业务返回值；HTTP / Socket 支持只读回执恢复。接口与边界见 [MUTATIONS.md](MUTATIONS.md)。

`call` 成功表示操作已完成，但不能据此判断各订阅是否已观察到该提交。snapshot / append 预测现在通过关联式权威确认或显示 TTL 移除，无关推送不能确认视图。网络失败或客户端取消也可能发生在服务端提交之后，需要保留“结果未知”这一状态。

已交付接口：

- **1A：操作结果（已交付）。** 可选 mutation 生命周期区分确定失败、读完成、写提交、Run / ingest 受理与结果未知；保留 `call` 默认返回业务结果的行为。发送后的不确定错误保留幂等键，恢复只查询 write/run 回执，缺失或过期仍为未知，不重放业务。
- **1B：视图确认（已交付）。** `mutation.views`、`CallOptions.confirm` 与 `subscription.confirm()` 在成功后发起带关联标识的刷新，服务端跳过旧视图缓存并返回匹配的完整快照；每份活跃订阅最多 32 个待确认请求。
- 结果未知时向应用保留幂等键和恢复入口；等待视图超时须返回明确的未确认状态。
- 一并明确新增线协议语义与能力协商；服务端和 SDK 同步更新，不保留旧协议实现。

完成条件：

- 1A 已验证发送前后取消的区别、认证刷新复用输入与键、提交后响应丢失、回执过期、规范化输入冲突与权限隔离。恢复失败不会把原未知结果改为确定失败；乐观预测到期也不改变未知状态。
- 以下视图确认保证已实现；TTL 到期仍只作为显示兜底，不会确认视图。
- 旧查询晚到、无关推送、缓存旧快照和 `refresh` 的 accepted 回执不能提前结束预测。
- 覆盖先推送后响应、连续写入、多个订阅分别确认、查询结果不变、过滤或删除导致记录不可见。
- 覆盖提交后响应丢失、幂等重试、重连、权限撤销，以及 delta 和 append 的回退。
- 确认范围限定为提交后重新读取的权威视图；过滤和分页仍按查询规则执行，多订阅分别更新。

关联标识只用于匹配请求与响应。Channel `seq`、Observer revision 和 Oban job ID 均不能作为数据库提交顺序。后续若引入副本读取或提交水位，需要另行定义一致性规则并测量成本。

## 阶段 2：共享客户端查询与 React 接入

进度：**已交付。** 核心提供 `selectSubscription`，独立的 [React 包](../../sdks/react/README.zh-CN.md)提供 Provider、`useQuery` 和确定的空 SSR 初始状态；[随记页面](../../examples/inbox-react/README.zh-CN.md)完成真实流程。核心默认保留最多 100 个活跃共享条目，React 查询存储固定为 100 个，参数编码上限为 64 KiB，最后一个引用释放后立即清理。

已交付：

- **已交付：**同一 client 内可选的引用计数查询存储，按身份上下文、查询名、结构化参数和传输模式区分。
- 纯函数 selector，以及使用 `useSyncExternalStore` 的独立 React 适配包；核心 SDK 保持框架无关。
- 一个 Inbox 或 Chat React 页面，展示共享订阅、参数切换、乐观更新与连接状态。
- 明确的 SSR 初始状态与请求隔离规则；首版采用确定的空初始状态。

完成条件：

- 两个组件使用相同查询时只有一份活动订阅；释放一个引用不影响另一个，最后一个引用释放后清理。
- 查询存储有明确的数量与内存边界；若保留无引用缓存，须定义容量、过期和淘汰规则。
- 不同参数、身份或模式分别保存，JSON 参数相等规则明确。
- Strict Mode、参数切换和重连不泄漏；无变更时 snapshot 引用稳定；SSR 水合初始状态一致。
- 退出、认证失效和 client 关闭后清理私有状态。

首版复用同一个查询的结果，Presence 句柄单独管理。不同查询里的同一 `id` 可能属于不同授权或字段投影，实体合并留待后续评估。

## 阶段 3：契约类型补全

进度：**已交付。** 生成器覆盖 operations/subscriptions 输入输出、Presence 名称与参数 / meta、操作 kind，以及显式的 `operationMetadata` 常量。`startRun` 按 kind 限制名称。每份契约必须为每个操作显式声明 `kind`，并声明 `presence` 段（未使用时为空对象）；发布前缺少这些字段的契约会在编译期被拒绝。

已交付：

- 生成 Presence 房间名、参数和 meta 类型，以及操作 kind 等类型信息。
- 按需导出显式运行时元数据，供能力判断和重试策略使用；TypeScript 类型与运行时策略分别处理。
- 将手写契约、生成契约和调用点统一到最终接口。

运行时元数据可辅助识别操作类别，能否安全重试仍由服务端事务与幂等保证决定。

完成条件：错误名称、meta 和输入在类型检查时失败；缺少操作 kind 或 Presence 声明的契约在类型检查时失败；正确示例可构建；生成结果与服务端导出一致；未声明能力的调用仍被拒绝。

## 阶段 4：短暂失败的有限重试

进度：**已交付。** `CallOptions.retry` 默认关闭，要求显式操作元数据，适用于 read/write/run；signal、cancel、ingest 不自动重试。最多 10 次、总时长最多 60 秒，默认 3 次 / 15 秒。读与确定拒绝后的调用可重新尝试；写入或 Run 一旦结果未知，后续仅查询回执，缺失或过期仍保留未知，避免超过幂等窗口后重放。进度通过 `pending.retry` 暴露；视图确认单独配置。

已交付：

- 固定幂等键，设置尝试次数和总时限，提供退避与抖动，并尊重服务端 retry-after 信息。
- 明确适用的受管调用范围，分别审查人工信号、摄取和其他入口的重试保证。
- 提供取消、超时和未知结果的可观察状态。

完成条件：服务端提交后丢失响应不重复写入；认证刷新与网络重试使用同一键；超出服务端幂等保留窗口不重放；权限、校验、CONFLICT 和协议错误不盲目重试；取消和总时限阻止后续尝试。

中断或超时不等于撤销服务端事务，外部副作用仍遵守各自的去重和对账规则。首版重试仅在当前客户端生命周期内进行，保持身份隔离。

## 阶段 5：登录桥接与完整应用验收

提供一个宿主后端从已验证登录上下文签发 Fyrlet 会话的完整示例，串起浏览器登录、会话续期和退出。密码、密码找回与 OAuth 授权服务交给现有身份系统。

进度：**本地示例与可选 PostgreSQL 宿主共享存储已交付。** 随记使用 OIDC 授权码、PKCE 与签名 ID token，覆盖续期、退出、撤销、换号、跨标签清理与 issuer 隔离。共享存储增加加密状态、登录 state 原子消费、串行续期、跨实例退出及重启恢复。测试使用真实本地 PostgreSQL 与签名测试 IdP；外部身份服务及生产多实例部署仍待验收。

完成条件：

- 覆盖登录、续期、退出、撤销和切换用户。
- 浏览器不能指定可信 subject 或读取服务密钥；外部 IdP 配置和身份映射经过验证。
- 不同 issuer 的相同外部用户名保持独立。
- 退出后清理订阅、预测和查询存储，并停止属于旧身份的后续尝试。
- 在真实页面串联写入确认、共享查询、类型化调用与可选重试，验证完整流程。

## 后续评估项

### 当前验收与性能工作

本地后续工作已补充分组验收入口、HTTPS／OIDC 部署预检查、Prometheus 连接池／积压告警、压测证据保护和重复速率扫描。事务内 PostgreSQL 失效通知通过 `FYRLET_POSTGRES_INVALIDATION` 显式启用，默认路径不变，监听断线后仍由周期对账恢复。命令、升级流程与外部门槛见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)。

速率扫描现可组合用户数／扇出密度，并支持新增／更新／归档／恢复／删除、分页历史和显式视图确认的混合负载；保留源码指纹、资源限额、正确性断言，每点至少三次重复，短测不等于容量。通道多路复用仍需证明剩余 Channel 内存是瓶颈，不因当前测量重写 VM／GC／NIF。CI 已统一冻结源码验收入口，另有恢复演练和长期采样工具；外部 IdP／生产共享宿主部署、新远程 CI、多主机故障、24 小时运行及真实注册表发布仍是独立门槛；已选择 Apache-2.0 与核心 + TypeScript + React 首发范围。

| 方向 | 启动条件 | 需要先解决的问题 |
| --- | --- | --- |
| 订阅通道多路复用 | 私有状态合入 Channel 后，进程内存仍是实测瓶颈 | 每份视图独立授权、ACK、到期与配额；与当前 Channel 基线对照后再决定线协议 |
| 实体与投影缓存 | 至少两个真实应用反复出现跨视图协调代码 | 显式实体定义、版本、字段权限、删除和引用计数；列表缺席不能视作全局删除 |
| 离线缓存与持久写入队列 | 有明确离线使用场景 | 数据过期、权限撤销、账号切换、冲突处理、幂等保留期与存储清理 |
| 生产部署补强 | 明确部署拓扑、负载和恢复目标 | 数据库就绪与连接池／积压告警规则已交付；生产阈值、混合负载、多主机故障和长期稳定性仍待验证 |
| 全局项目配额 | 产品要求严格的跨节点租户额度 | 分布式计数、一致性成本和故障时的限额策略 |

账号密码系统、完整客户端查询引擎、自有前端构建与移动打包工具暂不进入近期排期。新增抽象以实际应用需求和验证结果为依据。

## 发布前检查

按每次发布的实际范围确定检查项，不要求整份路线图完成后才发布。已有的本地打包、安装验收和遥测作为基础，重点补齐变更影响范围内的证据。

| 检查项 | 完成条件 |
| --- | --- |
| 协议与 SDK 一致 | 同步更新线协议和调用点；验证能力协商、未支持版本及错误处理 |
| 安装与升级 | 仓库外应用能从分发包安装、迁移和运行；明确支持版本的升级路径与失败后的恢复流程 |
| 运行可观测性 | 区分进程存活与数据库就绪；能观察连接池等待、任务积压、订阅恢复和未确认调用 |
| 负载与故障恢复 | 先写明连接数、订阅数、房间成员数、写入率和数据大小，再验证混合负载、重连及故障恢复；保留资源采样与正确性断言 |
| 分发与维护约定 | 已选择 Apache-2.0、核心／TypeScript／React 对齐版本与首发范围；实际发布前由维护者验证注册表所有权，并批准发布及兼容／弃用策略 |

## 交付与验证

每个阶段独立交付，包含公开接口、边界说明、相关测试和至少一个可运行示例。涉及协议或生成契约的变更，同步更新服务端、SDK 与中英文文档，并验证既有调用方式。

复用已有测试、遥测和压测工具。新增可靠性承诺通过故障与竞态场景验证；性能结论注明负载、拓扑和测量范围，遵守 [PERFORMANCE.md](PERFORMANCE.md) 的边界。完成后更新 [STATUS.md](STATUS.md)，验收证据归入 [ACCEPTANCE.md](ACCEPTANCE.md)。

下一步根据实际应用反馈迭代已交付接口，并补齐发布范围所需的远程 CI、外部 IdP、生产负载和多主机故障证据。P2 条目仍遵守各自的启动条件。
